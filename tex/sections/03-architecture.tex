\subsection{Architecture Overview}

As illustrated by the lower path of Fig.~\ref{fig:overview}, factorized
spatial/temporal attention exposes a \emph{matrix-axis mismatch}: the variable
sequence dimension $L$ appears on the output axis of $QK^{\mathsf T}$ but on
the reduction axis of $PV$. For the default \ModelName{} workload,
$T=\TemporalSeq{}$, $S=\SpatialSeq{}$, and $d=72$. Under classifier-free
guidance, spatial attention forms \SpatialContexts{} contexts of length $S$,
whereas temporal attention forms \TemporalContexts{} contexts of length $T$.
The same attention datapath must therefore alternate between long and short
output dimensions in $QK^{\mathsf T}$ and long and short reduction dimensions
in $PV$.

DARE addresses this asymmetry around a shared $36\times36$ INT8 processing
array. The array contains 36 output lanes, each evaluating a 36-product INT8
dot-product segment, for a total of \INTEightMACs{} INT8 MACs. Channel
sizes are naturally aligned with this granularity: the attention head
dimension is $d=72=2\times36$, while the STDiT hidden dimension is
$1152=32\times36$. Hence the dominant inefficiency is not the channel axis,
but the variable spatial/temporal token axis. The same compute cluster also
contains a \FPSixteenMACs{}-MAC FP16 VCU for softmax and other nonlinear
operations, \SRAMCapacity{} aggregate on-chip SRAM, and \DMAChannels{}
independent DMA channels providing \MemoryBandwidth{} aggregate bandwidth at
\Frequency{}.

The architectural principle is to reconfigure the interpretation and local
interconnection of the same arithmetic resources. In $QK^{\mathsf T}$ mode,
DARE changes how the 36 output lanes are assigned across heads; in $PV$ mode,
it changes how products are grouped into independent reductions. The PEA MAC
count itself is unchanged in both modes, which allows the two optimizations to
share the same datapath and memory hierarchy.

\subsection{Output-Axis Adaptation for $QK^{\mathsf T}$}

For one query row, $QK^{\mathsf T}$ computes $L$ attention scores, so the
sequence length directly determines output-lane occupancy. A conventional
mapping assigns all 36 output lanes to one attention head. Ignoring other
pipeline effects, its useful-lane fraction is
\begin{equation}
 \eta_{\mathrm{out}}(L;P)=
 \frac{L}{P\left\lceil L/P\right\rceil},
 \label{eq:qk_util}
\end{equation}
where $P$ is the number of lanes assigned to one head. With $P=36$, temporal
attention at $T=15$ uses only $15/36=\BaseTemporalQKUtil{}$ of the lanes,
while spatial attention at $S=405$ reaches \BaseSpatialQKUtil{} because the
last 36-lane group is only partially filled.

DARE introduces an output-partition mode in which the evaluated design divides
the 36 lanes into four independent 9-lane groups:
\begin{equation}
 36\ \text{lanes} \rightarrow
 4\ \text{heads}\times 9\ \text{lanes/head}.
 \label{eq:qk_partition}
\end{equation}
Each group produces score entries for a different head while reusing the same
physical MAC array. Temporal attention now completes one 15-score row in two
9-lane rounds, increasing useful-lane occupancy to
$15/18=\OursTemporalQKUtil{}$. For spatial attention,
$405/9=45$ exactly, eliminating the output tail and reaching
\OursSpatialQKUtil{}. Thus, the same partition improves the short temporal
case while preserving efficient execution of the long spatial case.

The key mechanism is the output-axis partition itself rather than a second
attention engine: DARE changes which head owns each output group and how many
score positions are issued per group, while the underlying 36-product dot
products remain unchanged. The $4\times9$ configuration is the evaluated
mapping for the target workload; the paper does not require a duplicated PEA
for spatial and temporal attention.

\subsection{Boundary-Aware Segmented Reduction for $PV$}

The same sequence length $L$ plays a different role in $PV$. Each output
channel requires a dot product across the attention sequence, so $L$ becomes
the reduction dimension. Padding every reduction independently to the 36-wide
PEA gives the theoretical multiplier occupancy
\begin{equation}
 \eta_{\mathrm{red}}^{\mathrm{pad}}(L)=
 \frac{L}{36\left\lceil L/36\right\rceil}.
 \label{eq:pv_pad_util}
\end{equation}
For a short temporal sequence, this leaves a large fraction of every beat as
padding even though products from subsequent output reductions are ready to
execute.

DARE instead treats successive $PV$ dot products as a continuous product
stream. A 36-product beat may therefore contain the tail of one reduction,
one or more complete reductions, and the head of the next reduction. Each
product group carries reduction-boundary metadata identifying the logical
segment to which it belongs. The reduction tree propagates both partial sums
and segment information; neighboring values are accumulated only when their
segment tags match, preventing products from different output reductions from
being mixed. Completed segments are committed to the output path, whereas an
unfinished tail is retained and combined with the matching segment in the
next beat.

By packing across reduction boundaries, DARE removes the padding between
successive dot products; only the final tail of the packed stream can remain
underfilled. This mechanism is complementary to the $QK^{\mathsf T}$ output
partition because it addresses the same irregular sequence dimension after it
moves from the output axis to the reduction axis.

\subsection{Dataflow and Reshape-Free Memory Access}

STDiT alternates logical $[T,S,C]$ and $[S,T,C]$ traversals between temporal
and spatial attention. Physically reshaping the activation tensor at every
mode transition would add SRAM traffic and buffering that are unrelated to
the attention arithmetic itself. DARE instead keeps the tensor in the shared
on-chip memory hierarchy and programs the load/address-generation unit with
the stride pattern required by the active logical view. The same SRAM contents
can therefore be traversed along the spatial or temporal axis without an
explicit transpose or reshape copy.

This address-level reconfiguration feeds both DARE execution modes: the
$QK^{\mathsf T}$ path receives the token order required by the selected output
partition, and the $PV$ path receives a continuous product stream together
with the corresponding reduction boundaries. The supporting address logic is
not a separate compute contribution; its role is to prevent data-layout
conversion from negating the utilization gains of the two PEA modes.
